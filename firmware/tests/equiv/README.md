# tests/equiv - the equivalence test rigs

The replay rigs and the allow-list every later stage compares against. A rig here is a test program that replays a
recorded game session (a capture) into firmware builds, or into a build and our model of the cart's chip, and compares
what they do. Stage 0 wrote the first two rigs, (a) `equivA.py` and (b) `rvboard.py`, on 2026-10-10; the others came in
later stages. The captures, the ROM and the reference sources stay outside the
tree; every path is an argument. How a number is known is said in words: measured, estimated or not known.

Words used below. Stages are the steps of the 0.3.0 work (see the stage list in `docs/ALLOWLIST.md`); "the stage-1
images" are the FW_S1 builds, "the stage-5 images" the FW_S5 builds `s5test` / `s5release` (our own song engine); test
build 4, 5, S2, S3a ... are the firmware builds B Jam tested on his own hardware. A1-A5 and B1-B59 are the rows of the
allow-list (`docs/ALLOWLIST.md`, `allowlist.json`). Captures were recorded in GPGX (the Genesis Plus GX emulator).
Unicorn is the CPU emulator library the RV32 (32-bit RISC-V) and chip rigs run on. The audit harness is our test
harness outside this tree that runs a firmware build against the cart chip's program; the cart-music runner (the
`"chip_runner"` path in paths.local.json) is the same kind of harness for the music. FZ1-FZ14, DEC and GO are the
named checks of the fuzz rigs; T-S2 / T-S3 / T-S5 are the transforms of `s1_scope.json`. A lockstep runs two sides
event by event and compares them after every event; a co-simulation runs the RTL and the firmware together.

## Exit codes (the rigs fail loudly)

Every rig ends with `RESULT: PASS` or `RESULT: FAIL: <reasons>`, writes `result` and `fail_reasons` into
`summary.json`, and exits **0 = PASS, 1 = FAIL, 2 = bad arguments / inputs**. FAIL = any per-post or checkpoint
difference outside the run's allow masks, an RV32 fault, no post replayed, and (equivA) an `--expect` digest mismatch,
a `G` globals difference or an argument block that left the recording; (rvboard) an interrupt enabled, an SRAM / XLINK /
unexpected IO access, a write into `wram_upper` or a stack overrun; (synth) the end checkpoints not equal on all three
sides or the synthetic list not posted. `--informational KIND` counts one of those model-integrity kinds without
failing. Measured: the check's F5 mutation (one row dropped) makes equivA and rvboard exit 1, the
clean tree exits 0.

`equivA.py --expect expected/host_final026.json:test_solo` checks the first side's chained digest against the
committed final 0.2.6 digests at every 1,000-frame mark reached, so a slice needs no reference executable.

## Input stream (both rigs)

`ppm_reset()` with the option word, then every capture record from power-on in order: RAMW (type 3) = a raw cart-RAM
write (68000 word A = MCU halfword A, byte A = MCU byte A^1; >= $2000 dropped); CMD (type 2) = the record's 16
argument words forced at $1E10 (as our earlier lockstep rig did; mismatches against the replayed RAM are counted: 0 on every capture),
then the post (`reg_cmd := word; ppm_cmd_handler()`). Nothing is skipped.

## What is compared per post

| item | (a) host vs host | (b) RV32 vs host |
|---|---|---|
| RAMDP 8 KB after the post (cart RAM + $1FE0-$1FFF) | every word | every word (board mode: VU words $1B98-$1BFF counted apart, allow-list A5) |
| FPGAIO (ctrl, time, sdram_ptr, vol_sfx, vol_bgm, stream_cnt) | all 24 bytes | all (board mode: time is modelled, excluded) |
| printf text (TEST) | exact | the printf ARGUMENTS formatted with C rules (allow-list A3) |
| audio entry points (sfx_*, mdp_*) with arg and $1E10-$1E15 | exact | exact (stubbed on both, A4) |
| SDRAM | changed granules + bytes after every non-AD post (AD changes compared at the frame's AF) | union of host-changed and RV-written granules, bytes |
| BRAM $000-$FFF | every post | every post |
| checkpoints (start, every N AFs, end) | SDRAM 8 MB, flash, BRAM 64 KB, RAMDP+FPGAIO | same |

### Stage 1: the chip lockstep

`chiplock_s1.py` replays a capture from power-on into three sides at once: the cart's program in the cart-music runner
on Unicorn (paths.local.json `"equiv"."chip_runner"`, read in place), the stage-1 host build and the final 0.2.6
host build. Every event (a post, a 9494 tick, the chip's frame time) is compared field by field with the reference
`s1_scope.json` names for that command: the register-write sequence, the stored words an MCU read returns, the bytes
the window serves (FIFO B, allowed transform T2 of docs/CART_FPGA_SPEC.md section 15.1) and the chip-written
cart-RAM words against the chip; cart RAM, pointer, volumes,
audio, save and SDRAM against final 0.2.6; the 68000's `$1FE4` by the composer rule. The chip's writes of later stages
(the song engine, MegaWire, the EEPROM driver, the load list, FIFO-B refills) are removed as named transforms, each
counted under its allow-list row. The chip runs 1/59.92 s of emulated time at every frame (`--no-frame-time` turns it
off: then 83's trim measures a zero period and refuses). `run_all.py --s1-rigs` runs `chiplock_slice.py` (~2 min);
the full corpora run as checkpointed segments of under ~9 minutes each:
